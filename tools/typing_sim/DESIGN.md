# 打字模拟评测系统（typing_sim）设计

> 2026-10-04 全量跑出的问题清单与修复方向见 `docs/typing_eval_findings.md`；
> 自动聚合数据见本目录 `REPORT.md`。

## 目的

按**正常人的打字习惯与主流输入法标准**，系统性、全自动地模拟打字并评估
XWX 引擎，暴露问题——不依赖人工挑样本。

## 依据的标准与公开方法论

1. **语料**：北京大学计算语言学研究所《人民日报》标注语料库 1998 年 1 月
   （`data/199801/199801.txt`，2.2 万句真实新闻，自带人工分词与词类标注）。
   这是中文 NLP/输入法研究最常用的标准参考语料；自带分词正好回答
   「用户是按什么单位打字的」。
2. **指标**（输入法评测通行的口径）：
   - 首选命中率（top-1）、首屏命中率（top-9，与 page_size 对齐）、目标词名次；
   - **词频加权口径**（2026-10-05 增）：词级样本是按词库分层抽的（每层封顶），
     与真实使用分布不是一回事——均匀口径下「2 字母简拼首选」约等于组内词数的
     倒数，测的是输入歧义度。故召回/首选各出一份按词条词频加权的读数；
   - **整句完全正确率**（原只有字转换相似度）与 **击键节省率 KSR**
     （Σ 实际击键 / Σ 全拼基准击键，基准 = 词的全拼字母数 + 一次上屏键）；
   - 字转换正确率 / 句转换正确率（整句全拼、零干预空格上屏的经典口径）；
   - 平均击键数/字（KSR 击键节省率的可比代用口径）；
   - 逐键延迟 p50/p95/p99（项目性能门槛 12ms）。
3. **简拼标准**（主流输入法通用约定）：
   - 简拼 = 各音节**首字母**；zh/ch/sh 支持两种写法：折叠（中→z）与
     全声母（中→zh），两种都应能召回；
   - 零声母音节（安/恩/二…）取其首字母；
   - 简拼多用于多字词（≥3 字）、成语、专名；二字词以全拼为主、简拼为辅；
   - 混合输入（全拼+简拼交错，如 `womenjtqbj`）是主流输入法标配能力。

## 打字习惯模型（可调，CLI 参数）

按词输入（打一个词 → 选字 → 继续），选字行为：
目标在前 9 位 → 对应数字键（第 1 位按空格，第 10 位按 `0`）；
目标不在候选里/超出首屏 → **记失败**，按空格上屏首位（模拟用户将就），
句子继续（保真上文链）。

词长 → 输入风格分布（`gen_plans.py` 参数）：
| 词长 | 全拼 | 简拼 | 混合 |
|---|---|---|---|
| 1 | 100% | – | – |
| 2 | 85% | 15% | – |
| 3 | 55% | 45% | – |
| ≥4 | 35% | 55% | 10% |

另有整句风格：部分句子整句全拼一次打出，连按空格直到上屏完
（测字转换正确率、LM 接力、残留串）。

## 四个系统性测试面（全部数据自动生成，零人工挑样本）

| 测试面 | 生成器 | 覆盖什么 |
|---|---|---|
| A 词级简拼/混合**全覆盖** | `gen_abbrev.py`（读 dict.bin 枚举全部词条） | 每个词 × 首字母串 × zh/ch/sh 折叠变体；混合缩写对 3~4 字词全枚举（2^n-1 模式），对长词采样 |
| B 句子级会话模拟 | `gen_plans.py`（人民日报语料） | 按习惯模型逐词打字+选字，走**真实 InputSession 状态机**（上下文接力、数字选词、标点收尾） |
| C 整句全拼零干预 | 同上（整句风格） | 字转换正确率、切分/beam/LM 排序 |
| D 逐键前缀稳定性 | 模拟器内置 | 每敲一键检查目标是否仍在候选/首屏——暴露「打字过程中候选闪烁、临门消失」 |

## 构件

```
tools/typing_sim/
├── DESIGN.md         本文件
├── gen_plans.py      语料 → 打字计划 JSONL（B/C/D 的输入）
├── gen_abbrev.py     dict.bin → 词级简拼/混合样本 JSONL（A 的输入）
├── report.py         汇总结果 → 问题报告（分类聚合 + 实例）
└── data/             语料与中间产物（不进 git）
crates/xwx_engine/examples/typing_sim.rs
                      模拟器：word 模式（查候选）与 session 模式（驱动会话）
```

契约（JSONL）：
- 词级样本：`{"input":"zgr","word":"中国人"}`（A）
- 打字计划：`{"id":…,"sent":…,"words":[{"text":…,"style":…,"input":…}],"punct":"."}`（B）
- 词级结果：`{input, word, found, rank, ncand, top3, ms}`（A/D 共用字段）
- 会话结果：`{id, sent, ok, keys, ms, words:[{text,style,input,found,rank,outcome,churn}], got}`（B/C）

## 装配纪律

模拟器用**生产同款装配**（dict.bin + abbrev.bin + syllable_graph.bin +
万象 .gram，同一批环境变量），缺件即报错退出——与 eval_rank.rs 同一原则，
绝不「没装万象还打印万象结果」。

## 问题暴露口径

report.py 把结果聚合为问题桶，每桶给计数、占比与可复现实例：
1. 简拼不可达（目标不在任何候选里）——按纯简拼/混合分开；
2. 首屏未命中（rank ≥ 9）与深排名（rank ≥ 30）；
3. 首选错误（rank > 0）——按词长/词频分层；
4. zh/ch/sh 折叠 vs 全声母写法的召回差；
5. 前缀抖动（可见→消失 / 首屏内震荡）；
6. 会话级异常（上屏文本 ≠ 期望选择、残留 preedit、标点被翻页吞掉）；
7. 延迟超 12ms 门槛的输入样式与实例。

## 全拼精确命中（`full` style，2026-10-05 补）

`gen_abbrev.py` 出的四种 style 全是简拼/混拼，**「把拼音打全」这一类没有样本**——
实测漏掉了一个真实问题：打全 `liji` 时，尾音节补全词（`li jie` 的理解）靠语言模型
排到精确命中（`li ji` 的立即）前面（详见 `docs/typing_eval_fixes.md` 八）。

`gen_full.py` 从同一批样本的 `syls` 直接拼出输入（输入 = 词条完整拼音，词频 ≥10 万、
2~4 音节、无分隔符），写出 `data/full_samples.jsonl`，用**同一条** `typing_sim --word`
跑，`style` 记为 `full`：

```sh
python3 tools/typing_sim/gen_full.py --out tools/typing_sim/data/full_samples.jsonl
cargo run --release -p xwx_engine --example typing_sim -- word \
  --in tools/typing_sim/data/full_samples.jsonl --out /tmp/full.jsonl
```

口径与其余 style 完全一致（召回 / 首选 / 首屏 / 词频加权），报告里并排显示。
