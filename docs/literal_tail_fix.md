# 完整尾音被补全抢位：修复与验收

## 问题与修复边界

真实词库与万象模型下，输入 `haihuika`，原来首位是「还会看」，「还会卡」没有进入结果。原因有两层：整句 n-best 被高分补全占满，随后排序又允许无词频的拼装候选凭 LM 把完整开音节追加成鼻音尾。这不是针对一个短语的特例。

本次修改：

- `crates/xwx_engine/src/engine/lookup_sentence.rs`：整词直达或不可能完整收尾的输入直接走原转换；其余整句调用专用搜索，不改变整句置顶判据。
- `crates/xwx_engine/src/engine/lookup_scoring/sentence.rs`：仅在所有中间边均为字面精确边时，共享普通／字面路径的前缀搜索。终点只存分数、父节点和边位置，不再构造后续不会使用的 LM 状态；同一前缀的末尾词共用上文准备，没有末尾词的位置不做这项准备。字面终点按原位置分组剪枝，保留稳定并列次序、束宽、编辑预算和浮点运算顺序。
- `crates/xwx_engine/src/engine/lookup_scoring/literal.rs`：中间含纠错、gap、简拼或模糊边时保留独立救援。仅在缺少整串字面候选、现存补全的已打尾部本身是合法音节、且格上有等长路径时触发。
- `crates/xwx_engine/src/engine/rank/mod.rs`：无词频的整句拼装候选不能仅凭 LM 把完整开音节补成 `n/ng` 并压过精确路径。保留词条词频支配豁免、已有 `n → ng` 豁免及没有精确对手时的补全；先检查分差，再计算鼻音形态，判据不变。

通用 `decode.rs`、`best_chain_candidates` 及其调用者保持本轮优化前的实现。没有短语白名单、删候选换速度、提高全局 beam 宽度或新增依赖。没有修改用户学习数据、安装或重启系统输入法。

## 功能验证

新增／保留以下回归测试：

- `crates/xwx_engine/src/engine/tests/literal_tail.rs`：合成词库的 `ka/ba/da/ma/li` 字面整句不被补全抢位，补全仍可选；真实词库、三种上文、逐键输入、追加 `n`、退格和空格上屏。
- `crates/xwx_engine/src/engine/tests/sentence_beam.rs`：Bigram、万象和 Mixed 模型，空／非空上文，`k=0/1/4/16`、两种逐词惩罚下，共享搜索与两次独立解码的路径、次序和 `score.to_bits()` 一致。
- `crates/xwx_engine/src/engine/tests/sentence_fallback.rs`：中间／末端的 gap、简拼、模糊、编辑、超预算与整词直达保持参考结果。
- `crates/xwx_engine/src/engine/tests/sentence_random.rs`：100 个确定性随机正向格，四种束宽，逐位比较两路完整路径与分数。
- 专用搜索模块中的断言遍历全部 `segmenter::SYLLABLES`，保证尾字母快路径不跳过任何当前合法完整音节。

引擎单测 **484 通过、0 失败**；全工作区 **619 通过、0 失败、2 项既有忽略**，包含私有 D-Bus 集成测试。全目标 clippy（`-D warnings`）及 release 主程序构建通过。

真实语料 daily、mixed、edits、keystrokes、tuning 加 11 个尾音样本，共 **60 条目标记录**：所有原目标排名不退化。`haihuika` 从未召回「还会卡」变为第 1，「还会看」仍保留；`haihuikan/haihuik` 仍首选「还会看」。其余前五不变。

全字段探针对比正确性参考版，共 **990 个查询／会话块全部逐字节相同**，包括候选顺序、分数字节、覆盖范围、英文与学习／模糊音组合。与修复前版本相比，原有 **989 块不变**：唯一预期变化是学习＋模糊音的逐键 `womenjintianquxi` 新增「我们今天去洗／吸」，排在原有「想／向」之前；原候选分数及后续按键结果不变。目标 `haihuika` 另由上述真实语料与会话测试覆盖。

## 性能口径与结论

**目标查询原先新增的耗时已消除，现版在目标场景稳定更快；现有复测未发现可稳定复现的常规路径回退。有限样本不等于证明任意输入、任意机器、每次按键都只快不慢。** 小幅上扬和不确定性保留如下，不因多数场景变快或低于 12ms 就自动判定无回退。

基线是前一轮已验收性能优化之后、尾音修复之前的工作区快照，不是 Git HEAD，也不是带额外救援的慢版。两版用同一 Cargo 命令和特性构建，真实词库、副索引、万象模型；逐键使用 Mixed 用户层和真实 `InputSession::handle`。只计引擎／会话，不含真实桌面 D-Bus、应用及候选窗。

## 已撤回方案

- 过宽字面救援曾影响残缺尾音、叠字母纠错，已收窄，未放宽旧断言。
- 将救援加入通用候选／解码函数曾使非目标 `nihao` P95 约 0.465 → 0.562ms，已撤回，通用热代码不动。
- 独立过滤格再跑 beam 的功能版，`haihuika` P95 **0.35170 → 0.49010ms（+39.35%）**，用户不接受；现版共享搜索替代，未以功能正确掩盖性能代价。
- 早期共享原型仍有 Mixed 短句变慢；现版增加调用端原路径、按需 LM 准备及等价条件短路，并以上述新进程／逐键对照复核，不复用早期的通过结论。
