## 0. 准备

### 不动系统的跑法（推荐先用这个）

`just install` 要 sudo、会写 `/usr/share/ibus/component/`、还会 `ibus restart`。
**先别用它**，用下面这个只写你自己家目录的方式：

```bash
cd ~/Desktop/xwx_ime

# 1. 数据文件就位（三个都要有）
for f in dict.bin abbrev.bin wanxiang-lts-zh-hans.gram; do
  printf '%-32s ' "$f"; [ -f ~/.local/share/xwx/$f ] && echo OK || echo 缺失
done
# abbrev.bin 若缺（简拼副索引，缺了第 18~21 条全废）：
python3 scripts/abbrev_to_bin.py && cp data/abbrev.bin ~/.local/share/xwx/

# 2. 装组件 XML 到用户目录（不用 sudo，整段可直接复制；须在项目根执行）
cargo build --release -p xwx_ime
mkdir -p ~/.local/share/ibus/component
BIN=$(cargo metadata --no-deps --format-version 1 \
      | python3 -c 'import json,sys; print(json.load(sys.stdin)["target_directory"])')/release/xwx_ime
"$BIN" --xml > ~/.local/share/ibus/component/xwx.xml
grep exec ~/.local/share/ibus/component/xwx.xml    # 核一眼路径对不对
```

> `--xml` 会**自动把当前二进制路径填进 `<exec>`**（`main.rs` 用 `current_exe()`），
> 不需要 `sed` 替换模板。上面这条已实跑验证，输出是
> `<exec>/mnt/hdd/target/xwx_ime/release/xwx_ime --ibus</exec>`。
>
> target 目录被 `.cargo/config.toml` 指到了 `/mnt/hdd/target/xwx_ime`，
> 所以用 `cargo metadata` 查而不是写死 `./target`。
>
> ⚠ 别写成 `--xml --exec <路径>`：`--exec` 后面的参数会被当成**输出文件名**
> （`main.rs:46` 的 `out_path` 判定是「不以 `--` 开头的第一个参数」），
> XML 会被写进那个文件而不是 stdout。

### ⚠ 和 fcitx5 的冲突

**你日常用的 fcitx5-rime 会占用 `org.freedesktop.IBus` 总线名**
（`justfile` 自己也警告了这条）。验证时二选一：

- **切到 IBus 会话**验证，验完切回来；
- 或临时 `fcitx5 -k` 停掉 fcitx5，验完再启动。

无论哪种，**都不要动 `~/.local/share/fcitx5/rime`**——那是你日常打字的配置。

### 前台跑引擎（看得见日志）

```bash
just dev        # debug 版，前台运行，Ctrl+C 退出
```

出问题时日志直接打在终端上，比装成服务好排查。

## 对拍判据（2026-10-03 第 4 步修订）：**首位 0 变化 + 漂移逐条点名**

**旧判据**「逐字节 0 变化」**作废**，理由不是「太严」而是**用错了口径**：它把
「分数刻度重算」和「正确答案被顶掉」混在一个数字里数。降级世界
（`DEMOTE_OLD_ABBREV_CHANNEL = true`）里旧简拼通道退出供给，同一个词的分数刻度会整体
重算（`为什么` −15.7892 → −4.1834），逐字节比对必然大面积不同；**但其中没有一次是首位变化**：

```
段数 90 · 逐字节相同 81/90 · **首位变化 0** · 条数变化 2 · 差异行 1207
```

**新判据**（脚本 `scripts/probe_diff.py`，退出码即判据①，可直接挂门槛）：

1. **逐段首位候选变化数必须为 0**（真退化的定义：正确答案被顶掉）；
2. 每条漂移**逐条点名**：报出该段条数变化与新增/消失的词，接受与否由人工核对理由。

复现：

```sh
export XWX_LM_PATH=$HOME/.local/share/xwx/wanxiang-lts-zh-hans.gram
EX=/mnt/hdd/target/xwx_ime/release/examples
$EX/regression_probe --format v1 --stdout 2>/dev/null | grep -v 'min_ms=' > new.txt
python3 scripts/probe_diff.py baseline_v1.txt new.txt   # 退出码非 0 ⇒ 首位有变化
```

**结论**：保留这条线等于禁止降级，而它拦下的那条输入在两个世界里**都不可用**。

**`zmg` 为什么在降级态更靠后（机制，不是「格子供给丢了」）**：两态都产满 100 条候选，
两态的 `zmg` 都是 `Abbrev, covered=3, freq=100`（覆盖整串的**词条级命中**，降级态里还按
词条口径重算过分数并升到精确档）。降级态的第 39~100 名**全是同一档 `freq=100` 的填充条目、
分数全等**（−19.4889 与 −20.9889 两档），名次由词面字典序决定：

```
#1  最敏感 freq=16005 score=-5.6789   …   #39 正面杠 freq=100 score=-19.4889
#68 怎么改 freq=100 score=-20.9889    …   #70 怎么敢 freq=100 score=-20.9889
```

默认态里同一条 tie group 只有前 45 名排在它前面（旧通道的收集早停 + 合并口径），降级态
是完整格子口径的 68 名。**差别不是「有没有这条读法」，而是「同分填充档里排在它前面的有多少条」**。

**为什么不选「把 zmg 的格子供给补上」**：真要把 `zmg` 从 68 提到第一页，必须把
`怎么改` 与 `怎么敢`/`怎么怪` 这一整片 `freq=100` 的同分条目**分开**——那是
131.5 万条（≈70%）条目没有真实词频的数据工程（已在看板卡 `t-murybinm-hwp8jk` 的
选项 C 里量化并否决）。同时 `zmgai`（同一类、完整输入）在降级态是 **第 1 名**，
说明这条路径的供给没坏。

**因此**：验收线写 **keystrokes ≥ 0.876 且 12 条逐条点名（除 `zmg` 外名次不得变差）**；
`zmg` 记为**已点名的已知差异**。
