## 3. 真实目标

用户留在中文模式输入英文时，不需要先切英文模式，就能：

1. 在英文意图明显时直接用首选上屏英文。
2. 少打几个字母，通过候选补全英文单词。
3. 随使用习惯调整英文排序。
4. 可选地在提交英文词后继续选择下一词。
5. 继续正常输入中文；短串、简拼、中文标点、网址和原文上屏不被破坏。

**目标不是“英文总在中文前面”，而是“打英文时英文靠前”。**

## 4. 交付范围固定为两个里程碑

### M1：必须先完成的基础能力

- wordfreq 常用词频底座，加少量明确维护的技术词和大小写覆盖。
- 独立英文精确查询、前缀补全；不改中文词库和中文 LM。
- 中英文意图分档混排，中文候选内部次序保持。
- 英文选择学习、独立英文用户文件、屏蔽与撤销。
- 连续英文单词的延迟空格处理。
- 构建、加载、安装资源接线；数据缺失时只关闭英文能力。
- 引擎、会话、D-Bus 测试，以及真实数据的排序和性能报告。

### M2：完成 M1 后实施

- 基于真实二元词频和用户词对统计的下一词召回。
- 上文参与英文前缀补全排序。
- 没有正在输入的字母时，显示可选的下一词候选。
- 独立预测状态和“提交后刷新”“刷新后透传”两种输出。
- 空格、回车、应用快捷键、焦点变化的完整回归。

M2 默认关闭，用配置显式开启；这是功能开关，不是允许省略 M2 实现。
如果本次只能完成 M1，交付中必须明确写“下一词预测未完成”。

### 本任务不做

- 不接云服务、LLM、神经网络或运行时 Python。
- 不实现英文自动纠错、自动改写、整句生成。
- 不识别任意连续串中的中英边界，例如不承诺 woyongpython 自动成为“我用 Python”。
  先选中文段，再在剩余组合或下一次组合输入英文，是支持的路径。
- 不改大写起头的既有直出行为；Shift+H 后输入 ello 仍按当前英文跟随逻辑直出。
  因此该路径不提供新补全，也不把逐字直出拼起来偷偷学习。
- 不改变 Ctrl+空格的纯英文透传模式。
- M1/M2 的英文输入键仅支持 ASCII 字母；don't、C++、HTTP2 等暂不作为新英文词条。
  原有网址、邮箱、大写、原文上屏路径继续负责相应文本。
- 不读取应用全文；当前 IBus 实现没有 SurroundingText 上下文协议。

## 5. 目标行为示例

以下是验收目标，不是当前项目的实测结果。

| 场景 | 预期 |
|---|---|
| hello / python / docker | 有可信英文条目且无强中文全拼证据时，英文首选 |
| pyth / docke | 可以补全 Python / Docker，英文意图明确时靠前 |
| an / he / you / can / women，无英文上文 | 中文保留首选，同时可选英文 |
| 先选 hello，再输入 you | 有英文上文时允许 you 成为首选 |
| nihao / zhongguo / zgr | 保护中文全拼、简拼；不是“切不开拼音就算英文” |
| pyth 后回车 | 原样提交 pyth，而不是 Python |
| 选 hello，再选 world | 输出 hello world；不在 hello 后预先写尾随空格 |
| 选 hello，空闲时再按一次空格，再选 world | 输出 hello world，不重复加空格 |
| 选 Python，再选中文“开发” | 输出 Python开发，不自动添加中英间空格 |
| 输入 xi'an | 沿用拼音强制切分，不删除撇号后当英文查 |
| 进入邮箱/网址识别态 | 唯一原文路径，不混入英文补全 |
| M2 开启，选 thank | 可显示 you 等下一词，但不能自动上屏 |
| 预测显示期间按空格/回车 | 关闭预测并透传原按键，不替用户选择预测词 |

## 6. 为什么必须独立通道

当前中文排序不仅使用 score，还使用覆盖范围、拼写层级和补全层级。
把英文伪装为 SpellingKind::Exact 或给英文加一个大分数，会污染这些结构判断。

固定架构：

    原始组合串
      ├─ 现有 lookup_candidates → 已排序、已过滤的中文候选
      └─ 英文词表与英文用户快照 → 已排序的英文候选
                       ↓
                稳定混排，不再次中文排序
                       ↓
                InputSession / IBus

这里“双通道”不等于开两个线程。一次按键内顺序调用即可，不引入线程池、异步竞态或锁等待。

## 8. 不可违反的总约束

1. 英文关闭或未装配时，旧查询结果、选词和按键透传保持原行为。
2. 英文 score 与中文 score 不跨语言直接比较。
3. 英文候选不进入中文 lattice、fill_covered、sort_candidates 或中文造词。
4. 只有真实选择并上屏才学习；浏览、查询、翻页、取消和预测展示都不学习。
5. 用户文件损坏时不得用空表覆盖原文件；查询/按键路径不做文件写入。
6. 英文用户文件不与中文用户文件混用；debug/release 分开，测试显式隔离所有路径。
7. 所有对用户输入的消费都基于原始输入字节数，不基于补全后单词长度。
8. 不扩大网址 recognizer，也不重新解释拼音撇号、中文标点和翻页键。
9. 不自动运行 just install、just dev 或重启真实 IBus；测试使用私有总线。
10. 禁止用大量硬编码单词分支替代排序逻辑，也不能靠删除难例让验收通过。

## 9. 验收口径

- 行为：小夹具精确断言 + 真实词库语料，两者都要有。
- 接线：真实子进程和 D-Bus 信号测试，不能只证明库函数可调用。
- 性能：release，冷启动单列；稳态按场景报告 p50/p95/max。
- 沿用项目稳态 p95 ≤ 12ms 的会话按键预算；它不等于所有样本绝对不超过 12ms。
- 英文新增开销目标为 p95 ≤ 1ms，属于待测目标，不是已有结论。
- 明确区分会话计算时间与含 D-Bus 的时间，不能混在一张表里冒充相同口径。
- 所有初始阈值必须经过独立调参集与验收集检查；不得声称文档常数已被实测标定。
