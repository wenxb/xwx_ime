# 1. 缺陷 / bug

## D1 · P0：用户模型更新不是原子操作，会发布空表并丢并发更新

**位置：**`crates/xwx_engine/src/user_lm/mod.rs:180–207`

- **触发：**一个线程执行 `learn/add_entry/block_candidate`，另一个线程同时查询、学习或 flush。
- **后果：**`clone_tables_for_write()` 用 `mem::take` 把共享表替换成空表，然后释放锁。直到 `commit_tables()` 前，其他线程读到的是空模型；两个写者还能互相覆盖。计数、造词、屏蔽表都受影响。
- **怎么改：**改成统一的 `mutate_tables`：写锁覆盖“取得可写表—修改—发布代号”全过程。给 `UserTables` 派生 `Clone`，使用 `Arc::make_mut`；独占时原地修改，有快照时才复制。禁止中途发布占位空表。
- **怎么验证：**在 `user_lm/tests.rs` 用 `Barrier` 控制两个写者和一个读者：最终计数必须等于总学习次数；已有屏蔽项在任何快照中都不能短暂消失。测试必须能在旧实现上失败。
- **代价：**1–2 人日，无新依赖。并发发生频率需实测，错误交错本身由代码确定。

## D2 · P0：标点 / 大写字符结束组合时，会静默丢弃未覆盖后缀

**位置：**`session/commit.rs:8–13`；`session/input.rs:85–91,188–200,218–225`，均位于 `crates/xwx_engine/src/`

- **触发：**输入 `womenjintian`，高亮只覆盖 `women` 的「我们」，按逗号或 Shift+字母。
- **后果：**`commit_selection()` 只拼接确认段和当前候选，随后 `reset()`；`jintian` 没有上屏，也没有保留。
- **测试问题：**`session/tests/commit.rs:304–323` 目前明确断言输出「我们，」并结束组合，**把丢后缀固化成了正确行为**。
- **怎么改：**保持“标点结束组合、一次提交”的既定方向，但提交文本必须是：`确认段 + 当前候选 + 未覆盖后缀原文 + 标点`；不得自动替用户选择余串候选。整串候选保持原样。
- **怎么验证：**覆盖逗号、冒号、问号、Verbatim、已有确认段、无候选，以及不同 `covered`；断言每段输入要么被候选解释，要么原样保留，不能消失。
- **代价：**1–2 人日。**这是旧交互行为修正，必须单列批准并解释旧断言的更改，不能偷偷更新基线。**

## D3 · P0：`--xml --exec PATH` 可能把 XML 写进可执行文件

**位置：**`src/main.rs:45–65`

- **触发：**执行 `xwx_ime --xml --exec ~/.local/bin/xwx_ime`，指定路径可写且不是正在执行的那个文件。
- **后果：**`out_path` 把 `--exec` 的参数当成输出文件名，随后 `fs::write` 截断目标。文档警告不能替代修复。
- **怎么改：**用小型顺序解析器消费参数；`--exec` 必须吃掉下一参数；输出路径只能来自独立位置参数。缺值、重复输出、未知参数返回错误。没有输出路径就只写 stdout。
- **怎么验证：**新增 CLI 集成测试，覆盖参数顺序、stdout、显式输出、缺值；预置目标文件并核对 `--exec` 不改变它的字节。
- **代价：**0.5 人日，不需要引入 clap。

## D4 · P1：flush 会清掉未落盘更新；正常停止也没有可靠兜底

**位置：**`user_lm/file.rs:193–194,278–282`；`src/main.rs:239–263`

- **触发：**
  1. flush 取快照后又发生学习，写完后无条件 `dirty.store(0)`。
  2. 学习不足 64 次，进程收到 SIGTERM。
- **后果：**新增计数还在内存，但已不再被视为脏数据；甚至退出 flush 也会跳过。定时器只在 `needs_flush()` 时写盘，**不是每 30 秒保存一次**。`just dev` 使用的普通 `kill` 正好不会触发 `ctrl_c()`。
- **怎么改：**使用“当前代号 / 已保存代号”，成功落盘只确认所写那一代；串行化 flush。增加 SIGTERM 退出路径；定时保存任意非零增量，64 次阈值只能作为额外触发。磁盘写入和 `sync_data` 放到阻塞工作线程。
- **怎么验证：**可控暂停在取快照之后，再学习一次，完成 flush 后必须仍为脏；再次保存、重开后计数完整。增加不足 64 次时 SIGTERM 保存测试及写入失败重试测试。
- **代价：**1–2 人日，依赖现有 Tokio/std。

## D5 · P1：翻页、显示高亮、数字选词、空格选词使用不同坐标

**位置：**`session/input.rs:249–255,345–354,374–385`；`crates/xwx_ibus/src/engine.rs:110–119,305–320`

- **触发：**`ni` → PageDown → 空格或数字 `1`。
- **后果：**页面变成第二页，但 `cursor` 没有移动；数字直接取 `candidates[0]`。界面显示第二页首项，上屏却可能是第一页的「你」。向下移动越过第一页后，显示又被钳到页内第 8 项，而提交仍用全局光标。
- **另一个协议问题：**只发送当前页的 lookup table，却把点击索引当成完整候选集的全局索引。`tests/paging.rs:251–265` 手工发送 `9`，不能证明真实面板会发送 `9`。
- **怎么改：**只保留一个权威全局选中下标；页码由它推导。数字映射为 `page_start + digit_index`。推荐给 IBus 发送完整候选表和全局 cursor，让面板与会话使用同一表；`round` 与不循环的导航策略一致。
- **怎么验证：**每页每个可见候选分别通过数字、空格、点击提交，断言“显示文本＝提交文本”；重点测末页不足 9 项、跨页上下移动。真实面板点击索引需实测。
- **代价：**2–3 人日。发送完整表的序列化增量要计入 12ms。

## D6 · P1：第二次 `CreateEngine` 必定构造非法 D-Bus 路径

**位置：**`crates/xwx_ibus/src/engine.rs:392–404`

- **触发：**同进程第二次调用 `CreateEngine("xwx")`。
- **后果：**路径变成 `/org/freedesktop/IBus/Engine/xwx-2`。D-Bus 对象路径不允许 `-`；本机 zvariant 校验也明确拒绝。
- **怎么改：**改用 `xwx_2`，先构造并校验 `OwnedObjectPath`，再注册。补生命周期释放，避免修好创建后对象一直累积。
- **怎么验证：**在私有总线上调用 Factory 创建至少三个实例；分别输入，验证状态隔离；释放后验证对象不再响应。不要继续只测试预导出的首实例。
- **代价：**路径修复及创建测试 0.5 人日；完整释放生命周期另需 1 人日。

## D7 · P1：识别态的数字和大写没有走“原文直通”

**位置：**`crates/xwx_ibus/src/ibus_proto.rs:146–157`；`session/input.rs:28–32,210–225,249–255`

- **触发：**逐键输入 `http://x1.com`、`a@b2.com`、`http://x/A`。
- **后果：**数字先变成 `Select`，大写先变成 `Verbatim`，因此绕过识别态的 `Char` 分支。`1` 可以选中回声并提前提交地址；其他数字可能透传到应用，造成次序错误。
- **怎么改：**保留真实可打印字符，**先按会话是否识别态决定原文插入，再决定数字选词 / 大写结束组合**。不要只给识别器补字符表。
- **怎么验证：**在 `tests/verbatim_url.rs` 用真实修饰键逐键发送上述输入，检查提交时机、最终字节、每键消费结果；同时钉住普通拼音数字选词和 Shift 行为。
- **代价：**1–2 人日，无新依赖。

## D8 · P1：URL “补点”逻辑制造了用户没输入的字符

**位置：**`crates/xwx_engine/src/session/input.rs:443–455`

- **触发：**直接输入 `wwwx` 或 `ftpx`，没有按句点。`wwwx` 已复现。
- **后果：**`refresh()` 根据字符串形状臆测之前发生过翻页，补成 `www.x`。编辑删除点也可能被重新补回。
- **怎么改：**删除无事件依据的补点。若保持当前延后识别规则，增加很小的 `pending_url_dot` 状态，只能由真实句点键产生；记录位置，其他编辑、选词、取消必须清除。查询刷新不得修改原始输入。
- **怎么验证：**对照 `wwwx` / `www.x`，以及句点后翻页、移动光标、退格、Esc；无句点输入的输出必须逐字节不含句点。
- **代价：**0.5–1 人日。

## D9 · P1：分隔符只约束格，没约束兜底；回声也不是原文

**位置：**`engine/lookup.rs:63–79,107–108,227–231`；`engine/decode.rs:191–219`

- **触发：**`xi'anq`、`zz'zz`，均已复现。
- **后果：**前者在 fallback 中按 `xian` 重新切分，召回「先」；后者回声提交的是清洗串 `zzzz`。
- **怎么改：**归一化结果同时保存 raw、clean、边界和坐标映射。fallback 必须接收边界并使用相同音节判据；回声的文本只能来自 raw。
- **怎么验证：**增加含前导、尾随、连续分隔符，以及“合法前缀＋错尾”的用例；逐个验证候选读法不跨音节边界，回车和回声选词都保留原文。
- **代价：**1–2 人日。含分隔符输入的旧结果变更应单列；无分隔符全拼必须对拍不变。

## D10 · P1：会话边界没有统一，跨焦点上下文和跨标点造词仍会泄漏

**位置：**`session/commit.rs:158–179,194–203,284–312`；`session/input.rs:199,224`

三个可独立复现的问题：

1. `reset_for_focus_change()` 不清 `committed_tail/last_word`，复用实例时下个输入焦点仍继承前词，并学习跨焦点 bigram。
2. 拼音非空时的标点 / Verbatim 分支只 `push_tail`，不结算 `coin_buffer`。现有 `coin.rs:40–72` 只测试**空闲时**打标点。
3. 超过 24 字时调用 `break_coin_run()`，但 `is_reusable_phrase()` 没有长度检查，反而可以造出 25 字词。当前上限测试只检查缓冲被清掉。

- **怎么改：**集中定义焦点、标点、原文、模式切换的结算动作：焦点清 LM 上下文；标点结束造词段；模式切换即使空闲也结束造词段；造词资格显式检查 `2..=MAX_COIN_CHARS`。不要顺带改已有标点后的 LM 接续政策。
- **怎么验证：**在同一实例上跨 FocusOut/FocusIn 验证计数；逐字选择过程中用标点结束，再输入下一段；检查 24/25 字实际 entries 内容，而非仅缓冲长度。
- **代价：**1–2 人日。

## D11 · P1：损坏用户文件会在下一次学习后覆盖唯一副本

**位置：**`crates/xwx_engine/src/user_lm/file.rs:87–109,118–175,259–282`

- **触发：**文件中一行损坏或读取失败；随后用户正常学习并触发 flush。
- **后果：**加载回退为空模型，但仍保留原写入路径；下一次 flush 用新空起点覆盖原数据。
- **怎么改：**区分“不存在”和“读取/解析失败”。后者进入本次只读恢复状态，自动回写禁用；显式恢复时先保留原件，再写新文件。临时用户数据文件使用 `0600`。
- **怎么验证：**给计数区、造词区和屏蔽区分别注入坏行，学习、flush 后核对原文件哈希不变；权限错误也不能转成覆盖。
- **代价：**0.5–1 人日。

## D12 · P2：公开查询入口允许非 ASCII 进入按字节切片的排序代码

**位置：**`engine/lookup.rs:39–41`；`engine/rank.rs:192–220`

- **触发：**调用 `lookup_candidates("你", …)`；已复现 panic。
- **后果：**库调用方和探针可以直接击穿进程。下层“非 ASCII 返回空”没有覆盖最后的排序。

- **代价：**0.5 人日。

## D13 · P2：容错的“整条路径一次编辑”实际上没有被表达

**位置：**`engine/mod.rs:148–156,240–267`；`engine/lattice.rs:88–109,443–455,520–522`

- **触发：**容错格含可串联的多条编辑边。
- **后果：**`typo_edits` 只限制单次链枚举；落成 `LatticeEdge` 后只剩罚分，没有编辑次数。后向 DP 因而无法限制整条路径的累计编辑数。

- **怎么验证：**先构造两条各一次编辑才能到终点的人工格：预算 1 必须不可达，预算 2 才可达；再检验真实 typo 矩阵。真实输入的可见影响**需实测**。
- **代价：**1–2 人日。不要直接放宽成多次编辑来迎合当前结果。

**已知的 `en` 问题不作为新发现重复列出。**它仍应冻结在独立行为变更中：`dict/lookup.rs:421–425` 的修订必须有受影响输入清单，不能夹进上述重构。

# 2. 架构与结构

## A1 · P1：把“输入解释结果”变成共享数据，不再各路重新猜

**位置：**`engine/lookup.rs:63–88`、`engine/rank.rs:48–69,147–156`、`dict/mixed.rs:72–105`、`segmenter.rs:294–315`

**问题：**归一化、音节可达性、覆盖长度各有实现。排序用候选规范拼音长度推断消费位置，而容错、混拼前缀的真实消费位置并不等于它；`unreachable_tail` 也没有调用 üe 归一化。

**落地：**新增内部 `NormalizedInput`，集中 raw/clean/边界/映射；共享规范音节匹配原语，但保留各通道已有枚举顺序和预算。排序逐步改用真实 clean coverage，不以拼音长度替代。

**必须写成测试的不变量：**

- 非回声候选从输入位置 0 开始，消费范围合法且非零。
- `'` 不允许**音节**跨越；多音节词可以跨越音节之间的分隔符。
- 补全可以补足当前音节，不能凭空增加未输入音节；旧 `en` 例外单列冻结。
- raw、clean、规范拼音是三种不同坐标/表示，不能混用。

**验证：**规范化性质测试＋逐候选 coverage 对拍；行为修订与纯结构提交分开。  
**代价：**2–3 人日。

## A2 · P1：召回来源、拼写类型和候选配额被混成了一个概念

**位置：**`dict/lookup.rs:291–338`、`engine/lattice.rs:170–241`、`engine/rank.rs:327–359`、`engine/lookup.rs:173–182`

**问题：**

- `abbrev_candidates` 也返回 `Exact` 补全，却一并占“简拼池”的保底配额。
- 前缀混拼已不再覆盖整串，但排序仍把所有 `Abbrev` 当完整覆盖。
- 简拼配额分配之后，容错又直接排序截断，最终列表没有统一配额保证。
- 按 `(word,pinyin)` 去重，不能表达同词同读音但消费范围不同的读法。

**落地：**引入内部 `RecallHit`，分别保存来源、拼写类型、消费范围、编辑数；词典层返回词条和匹配证据，引擎负责打分和最终名额。先显式表达现有政策，再逐项修正；不要一口气重排。

**验证：**人工构造精确/补全/缩写/容错同词冲突，以及满 100 条时的配额案例；同时保留现有“屏蔽后不补位”的删除契约。  
**代价：**3–4 人日。默认不变更任何正常全拼候选。

## A3 · P1：一次查询应使用同一代用户数据

**位置：**`engine/lattice.rs:44–48,312,372`、`lm/mod.rs:384–388`

**问题：**格构建、beam、后向 DP、首词评分、简拼评分、屏蔽过滤分别取快照。即使修完 D1，一次查询仍可能混用不同代的 entries、counts、blocklist。

**落地：**查询开始取得一个 `QueryContext`，包含用户快照、词频总量、规范化输入；所有阶段复用。再逐步把用户存储访问从 `LmStore::Mixed` 的内部抽出，避免“查用户词典必须穿过 LM 枚举”。

**验证：**在阶段边界注入一次学习/删除：本次查询全用旧代，下次全用新代。  
**代价：**1–2 人日。

- **验证：**随机小格穷举验证“可达 ⇔ beam 非空”；完整候选和分数逐字节对拍。

## P2：去掉查询内重复字符串复制和无用 LM 状态推进

## P2：混拼仍有重复预处理和“预算之外”的工作

**位置：**`dict/lookup.rs:104–127,141,212`、`dict/mixed.rs:119–200,330–383`

- **改法：**音节长度序与首字母桶用 `OnceLock`；同一次查询复用全拼可达性结果；T2 前缀回溯复用 DP 前驱，避免每个前缀重跑。词块改为借用迭代器，分别统计记录探测和词条物化预算。
- **收益：**消除每查询排序/建桶，以及重复前缀 DP；现有 20,000 步限制没有覆盖全部词条解析、分配和输入长度成本，不能称任意输入常数耗时。

- **代价：**1–2 人日。

## P1：建立真正的性能验收入口

**位置：**`examples/{decode_bench,lookup_bench,regression_probe}.rs`、`tests/support/harness/keys.rs:19–24`、`justfile:34–43`

**实施测量矩阵：**

2. **会话层：**逐键输入每个前缀，包含退格、中间插入、确认一段后继续、选词和删除。

**代价：**2 人日，不需要重量级 benchmark 框架。

# 7. 实施顺序

## 第一批：小、稳，先阻止损失和错误上屏

**顺序：**

1. D3 CLI 参数解析。
2. D1 用户表原子更新 → D4 代号式 flush/SIGTERM → D11 损坏文件保护。
3. D6 Factory 合法路径。
4. D5 翻页选词一致性。
5. D2 输入后缀守恒、D7/D8 原文保真、D9 分隔符完整链路、D10 会话边界。
6. D12 非 ASCII 入口保护；同时落地 A4、Q1 的真实会话探针。

**验收：**

- `just verify`，clippy `-D warnings`。
- 未批准范围内的全拼候选、次序、拼音、分数逐字节不变。
- 每个 bug 都有旧实现必失败的定向测试。
- 修正错误交互的 golden 单独批准，不能覆盖旧证据。
- 至少用生产装配测逐键 p50/p95/max；不得以原有 `min_ms` 代替延迟验收。

## 第二批：建立可信性能线，再做等价优化

**顺序：**

1. 完成真正的查询/会话/D-Bus 性能入口。
2. A3 单查询快照。
3. 用 DAG 可达性替代生产 beam。
4. 首键预热、去重复分配、静态音节预处理。
5. A1/A2 逐步显式化坐标、来源和配额；D13 单独修。
6. Q3 必需数据测试、Q4 数据发布契约、Q5 离线安装验收。

**验收：**

- 纯优化提交全量对拍零差异，浮点不接受“近似相同”。
- 首键、首次 typo、热键分别报告；真实用户规模及 flush 并发场景纳入。
- 热路径 ≤12ms；报告超线次数和输入，不只报告平均数。
- 同代数据可重建、错误数据可拒绝、空 HOME 离线安装可输入。

## 第三批：用户价值功能，按此顺序做

1. **IBus 中英 Property。**
2. **用户词典管理 / 解屏蔽。**
3. **确认段上下文、个人化补召回。**
4. 基础编辑、标点、轻量配置。
5. 受控中英混输和快捷短语。

**验收：**

- 新能力关闭、空用户模型时，既有全拼逐字节不变。
- 有状态功能验证确认、取消、退格、焦点切换、重启后的完整序列。
- 个人化继续使用 `USER_COUNT_GAIN_R = 1000` 的计数增益。
- 无运行期网络；新增依赖与数据体积必须在提交说明中列出。
- 每项都通过同一套逐键 12ms 验收；双拼、云同步和大规模排序重做不进入本批。
